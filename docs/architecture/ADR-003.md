# ADR-003 — Uso de Repository para acceso a persistencia

**Estado:** Aceptado.

## Contexto

EduTech Academy necesita almacenar y recuperar información académica, como cursos, estudiantes, inscripciones, pagos y calificaciones.

Las entidades del dominio no deben depender directamente de las instrucciones SQL ni de la tecnología de almacenamiento utilizada.

El BRD identifica problemas relacionados con información distribuida en archivos separados.

## Decisión

Se adopta el patrón **Repository** para abstraer las operaciones de acceso a datos.

Los servicios de aplicación utilizarán repositorios para recuperar y guardar los agregados.

La persistencia y las transacciones se coordinan mediante **Unit of Work**.

## Alternativas consideradas

- **Active Record:** integra la persistencia dentro de las entidades, aumentando el acoplamiento.
- **Acceso directo a la base de datos:** simplifica algunas consultas, pero introduce dependencias técnicas en el dominio.

## Consecuencias

**Ventajas:**
- Independencia del dominio respecto al motor de base de datos.
- Mayor facilidad para realizar pruebas automatizadas.
- Centralización de operaciones de persistencia.
- Mejor control de transacciones.

**Desventajas:**
- Necesidad de implementar interfaces y repositorios.
- Mayor cantidad de componentes arquitectónicos.

## Evidencia de implementación

`src/edutech/infrastructure/db.py`

Contiene los componentes de persistencia y Unit of Work utilizados por la aplicación.

La solución utiliza SQLAlchemy para las operaciones de almacenamiento.

## Trazabilidad

RNF-02, RNF-03 y los problemas de información fragmentada identificados en el BRD.
