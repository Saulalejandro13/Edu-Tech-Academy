# ADR-002 — Uso de Service Layer para coordinar casos de uso

**Estado:** Aceptado.

## Contexto

Los casos de uso de EduTech Academy involucran distintas entidades y procesos.

Por ejemplo, una inscripción requiere consultar estudiantes, cursos, grupos y disponibilidad, además de registrar información académica y coordinar pagos.

Si estas operaciones se implementaran directamente en los controladores de la API, aumentaría el acoplamiento y se dificultaría el mantenimiento.

## Decisión

Se adopta **Service Layer** para coordinar los casos de uso.

Esta capa recupera los objetos necesarios, invoca los comportamientos del dominio, coordina operaciones y administra su persistencia.

Las reglas de negocio permanecen dentro del Domain Model.

## Alternativas consideradas

- **Lógica directamente en controladores:** solución sencilla inicialmente, pero genera controladores complejos.
- **Transaction Script:** permite implementar cada operación por separado, aunque puede duplicar lógica de negocio.

## Consecuencias

**Ventajas:**
- Separación entre coordinación y reglas de negocio.
- Mayor reutilización de funcionalidades.
- Facilita pruebas y mantenimiento.
- Permite que diferentes interfaces utilicen los mismos servicios.

**Desventajas:**
- Introduce una capa adicional.
- Requiere definir responsabilidades entre servicios y entidades.

## Evidencia de implementación

`src/edutech/application/services.py`

Contiene servicios de aplicación encargados de coordinar inscripciones, pagos, asistencia, evaluaciones y certificación.

## Trazabilidad

US-01 a US-19, RNF-01 y EX-01 a EX-04.
