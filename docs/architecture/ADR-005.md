# ADR-005 — Uso de Value Objects para conceptos sin identidad

**Estado:** Aceptado.

## Contexto

En EduTech Academy existen conceptos que se definen por sus valores y no necesitan una identidad independiente.

Entre ellos se encuentran Cupo, Nota, Dinero, Modalidad, CalendarioCurso y PorcentajeAsistencia.

Utilizar únicamente tipos primitivos puede provocar validaciones repetidas e inconsistencias.

## Decisión

Se adopta el patrón **Value Object** para representar conceptos sin identidad propia.

Estos objetos encapsulan sus validaciones y ayudan a garantizar que los valores utilizados por el dominio sean válidos.

Por ejemplo:
- Cupo: mínimo de 5 y máximo de 25 estudiantes.
- Nota: valor entre 0 y 100.
- Calificación aprobatoria: mínimo 70.

El diseño original también contempla representar explícitamente los estados de los procesos académicos.

## Alternativas consideradas

- **Tipos primitivos:** almacenar las propiedades como números, cadenas o valores booleanos sin objetos especializados.
- **Campos simples con validación externa:** ejecutar las validaciones desde los servicios o controladores.

## Consecuencias

**Ventajas:**
- Validaciones centralizadas.
- Reducción de duplicación.
- Mayor expresividad del modelo.
- Menor posibilidad de valores inválidos.

**Desventajas:**
- Mayor cantidad de clases.
- Necesidad de diseñar correctamente las restricciones de cada objeto.

## Evidencia de implementación

`src/edutech/domain/model.py`

La implementación actual utiliza principalmente los objetos Cupo y Nota.

**Alcance:** otros Value Objects contemplados en el diseño siguen pendientes de implementación completa.

## Trazabilidad

BR-01, BR-06, US-04, US-08, US-10 y las reglas de cupo y calificación del BRD.
