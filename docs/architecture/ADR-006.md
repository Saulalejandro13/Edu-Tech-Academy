# ADR-006 — Uso de Domain Events para comunicación entre procesos

**Estado:** Aceptado como decisión arquitectónica.

## Contexto

Algunos procesos de EduTech Academy producen consecuencias en distintas áreas del sistema.

Por ejemplo, cancelar un curso puede requerir procesos de reembolso, reinscripción y registro en bitácora.

Si los componentes se comunicaran mediante llamadas directas, aumentaría el acoplamiento y se dificultaría incorporar nuevas funcionalidades.

## Decisión

Se adopta el concepto de **Domain Events** para representar acontecimientos relevantes del negocio.

Entre los eventos identificados se encuentran:

- InscripcionRealizada
- PagoRegistrado
- CursoCancelado
- CalificacionModificada
- CambioGrupoAutorizado
- CertificadoEmitido

Estos eventos permiten representar las consecuencias de una operación sin establecer dependencias directas innecesarias entre componentes.

## Alternativas consideradas

- **Llamadas directas entre componentes:** solución sencilla, pero genera dependencias fuertes.
- **Coordinación completa desde Service Layer:** centraliza el flujo, aunque puede aumentar la complejidad de los servicios.

## Consecuencias

**Ventajas:**
- Menor acoplamiento.
- Mayor extensibilidad.
- Facilita incorporar procesos adicionales.
- Mejora la representación de acontecimientos del negocio.

**Desventajas:**
- Los flujos pueden ser más difíciles de seguir.
- Requiere administrar adecuadamente la publicación y el procesamiento de eventos.

## Evidencia y alcance

La arquitectura de Unidad 3 identifica los Domain Events anteriores.

La implementación complementaria registra acontecimientos mediante servicios y bitácora, pero **no implementa completamente un mecanismo desacoplado de publicación y suscripción de eventos de dominio**.

## Trazabilidad

US-09, US-11, US-12, US-13, US-15 y RNF-03.
