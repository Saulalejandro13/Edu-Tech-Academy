# ADR-004 — Uso de Aggregates como límites de consistencia

**Estado:** Aceptado.

## Contexto

En EduTech Academy existen objetos relacionados que deben conservar reglas consistentes.

Por ejemplo:

- Curso administra información relacionada con grupos y evaluaciones.
- Inscripción se relaciona con pagos.
- RegistroAcadémico agrupa asistencia y calificaciones.

Modificar estos objetos de manera independiente puede provocar inconsistencias en cupos, pagos y expedientes académicos.

## Decisión

Se adopta el concepto de **Aggregates** de Domain-Driven Design.

Cada agregado tiene una raíz responsable de controlar los cambios y proteger sus invariantes de negocio.

Los objetos internos no deben modificarse directamente desde componentes externos.

## Alternativas consideradas

- **Modificar directamente las entidades internas:** facilita algunas operaciones, pero debilita la consistencia.
- **Modelar todas las entidades de forma independiente:** aumenta el riesgo de operaciones incompletas o inválidas.

## Consecuencias

**Ventajas:**
- Protección de las reglas de consistencia.
- Control sobre las modificaciones.
- Reducción de operaciones inválidas.
- Definición de límites transaccionales.

**Desventajas:**
- Requiere establecer cuidadosamente los límites de cada agregado.
- Algunos procesos necesitan coordinación entre varios agregados.

## Evidencia de implementación

`src/edutech/domain/model.py`

La implementación actual incluye comportamientos asociados a Curso e Inscripción.

**Alcance:** el modelado de agregados se encuentra implementado parcialmente respecto a la arquitectura completa definida en Unidad 3.
